# Security policy

SENTINEL X is an experimental open-source defensive prototype, intended for
single-user local operation. Source-code publication is not a public-hosting,
scanning or exploitation authorization. Servers bind only to `127.0.0.1`.
No security certification, support SLA, bounty or response deadline is promised.

## Report a vulnerability privately

Use GitHub's **[Report a vulnerability](https://github.com/JLV-73/sentinel-x/security/advisories/new)**
flow from the repository's [Security page](https://github.com/JLV-73/sentinel-x/security).
A GitHub sign-in is required to submit. Verify that you are in the private reporting
flow, not a public Issue or Pull Request. The owner enables and verifies this channel
as part of the public launch; it creates no promise of immediate monitoring.

If the control is temporarily unavailable, contact @JLV-73 through an already
established private owner channel. If no such channel exists, wait for one to be
established; do not disclose details publicly. No new inbox is designated here.

Do not put secrets, private computer paths, personal data, databases, raw dumps or
unredacted logs/screenshots into ordinary Issues/PRs, even for evidence. Share only
the affected version/branch, concise impact, sanitized reproduction and minimum
necessary proof. Agree a private transfer route for any sensitive evidence.

Reproduce only in a disposable local instance with authorization and synthetic
fixtures. Never probe third parties or other users' installations. Source refresh
is not a security test. Credentials must be revoked/rotated with their provider,
not repeated in a report.

The owner decides triage, remediation and coordinated disclosure. P0.1 is stable;
P1-A is development, not an SLA or supported-version matrix. Releases need JLV GO.
Non-sensitive functional bugs use the regular bug-report form.
